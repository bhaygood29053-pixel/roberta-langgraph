# Targeted Pyramid practice gate

Issue #181 implements the `targeted_pyramid_practice` gate emitted by source-grounded Pyramid reconstruction.

## Purpose

Targeted practice asks Roberta fresh questions from the weakness groups diagnosed by the authoritative regrade. It is a verification step between source-grounded reconstruction and a new canonical Pyramid attempt.

It does **not** rewrite historical checkpoints, mutate the Pyramid training ledger, authorize retention, promote memory, declare source truth/live-state truth, mutate governance, or authorize execution.

## Input bindings

`roberta-pyramid-practice` requires four evidence inputs:

1. a validated Pyramid curriculum;
2. the exact `practice_questions.jsonl` generated by remediation;
3. the remediation plan that selected those practice questions;
4. the source-grounded reconstruction JSONL covering every original weak item.

The practice JSONL is only a selector. Every row is resolved back to the validated curriculum and must match its level, concept/subconcept, question text, source refs, and integrity flag exactly. Original weak exercise IDs cannot be reused as fresh practice.

The reconstruction input must cover every original weak exercise exactly once, be source grounded, have `evidence_packet_status=ok`, contain evidence anchors, retain `targeted_pyramid_practice` as its next gate, and keep all authority flags false.

## Verification policy

For the selected Pyramid level:

- overall practice accuracy must meet the level's normal pass floor;
- every noncritical weakness group must independently meet that same accuracy floor;
- every weakness group that contained an original critical failure must achieve 100% PASS on its fresh practice questions;
- no practice answer may create a new critical failure.

Only when all gates pass is `CANONICAL_ATTEMPT_AUTHORIZED true`, with next gate `new_canonical_level_1_attempt` for Level 1 remediation. This authorization means only that a new canonical attempt may be started with a new seed.

## MB4E Level 1 command

After issue #181 is merged and installed locally:

```bash
roberta-pyramid-practice \
  --curriculum "$HOME/.roberta/curricula/mastering_blockchain_4e_2023_provenance" \
  --practice .roberta/pyramid_remediation/mastering_blockchain_4e_2023_book01/3f5f278c645b9e73-provenance/practice_questions.jsonl \
  --remediation-plan .roberta/pyramid_remediation/mastering_blockchain_4e_2023_book01/3f5f278c645b9e73-provenance/remediation_plan.json \
  --reconstructions .roberta/pyramid_reconstruction/mastering_blockchain_4e_2023_book01/3f5f278c645b9e73-provenance/source_grounded_reconstructions.jsonl \
  --output .roberta/pyramid_practice/mastering_blockchain_4e_2023_book01/3f5f278c645b9e73-provenance \
  --batch-size 10
```

The output directory contains restart-safe practice checkpoints plus:

- `practice_results.jsonl`
- `practice_report.json`

No canonical Pyramid ledger path is accepted or written by the practice runner.
